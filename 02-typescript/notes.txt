6. Objects

You can describe the shape of an object directly:
let user: {
  name: string;
  age: number;
  isAdmin: boolean;
} = {
  name: "Kesavan",
  age: 28,
  isAdmin: false
};



interface User {
  name: string;
  age: number;
  phone?: string;
}
Now both are valid:
const user1: User = {
  name: "Kesavan",
  age: 28
};
and:
const user2: User = {
  name: "Kesavan",
  age: 28,
  phone: "9876543210"
};


8. Tuple
A tuple is an array where the position and type of each element are known.

For example:
let user: [string, number] = ["Kesavan", 28];

const product = {
  name: "Laptop",
  price: 55000,
  inStock: true,
  tags: ["electronics", "laptop"]
};

We can describe that structure in TypeScript:

interface Product {
  name: string;
  price: number;
  inStock: boolean;
  tags: string[];
}

Then:

const product: Product = {
  name: "Laptop",
  price: 55000,
  inStock: true,
  tags: ["electronics", "laptop"]
};


functions:
In TypeScript, we can type both the parameters a function receives and the value it returns.

function add(a: number, b: number): number {
  return a + b;
}

The syntax is:

(parameters): returnType

So:

function greet(name: string): string {
  return `Hello ${name}`;
}


When would we explicitly write the return type?

It can be useful when:
the function is important/public
the return type is complex
you want to enforce the function's contract
you want clearer code
you're working on larger applications

We can describe the function itself with a type:

let calculate: (a: number, b: number) => number;

This means:
calculate must contain a function that accepts two numbers and returns a number.

So this works:
calculate = (a, b) => {
  return a + b;
};

};


. interface declaration merging

Here's an important difference.

You can declare the same interface more than once:

interface User {
  name: string;
}

interface User {
  age: number;
}

TypeScript combines them.

The final User is effectively:

interface User {
  name: string;
  age: number;
}


A normal type alias cannot be redeclared like this:

type User = {
  name: string;
};

type User = {
  age: number;
};

That causes an error.


Use type when you need unions/intersections or other type compositions
type Status = "pending" | "success" | "failed";
type ID = string | number;

Partial

const user: User = {
  name: "Kesavan",
  email: "kesavan@example.com",
  age: 28
};

All three properties are required.

But imagine an update user API.

The user might update only their name:

{
  name: "Kesavan Kumar"
}

We don't want to require email and age.

That's where Partial helps:

type UpdateUser = Partial<User>;

Conceptually, TypeScript transforms it into:

type UpdateUser = {
  name?: string;
  email?: string;
  age?: number;
};



Required<T>

Required does the opposite.

Suppose:

interface User {
  name: string;
  email?: string;
}

Normally this is valid:

const user: User = {
  name: "Kesavan"
};

But:

type CompleteUser = Required<User>;

Now CompleteUser becomes conceptually:

type CompleteUser = {
  name: string;
  email: string;
};




Pick<T, K>

Pick lets you select only certain properties from an existing type.

Suppose:

interface User {
  id: string;
  name: string;
  email: string;
  password: string;
  age: number;
}

Maybe your profile page only needs:

name
email

Instead of creating another interface manually:

interface UserProfile {
  name: string;
  email: string;
}

you can write:

type UserProfile = Pick<User, "name" | "email">;

Now:

const profile: UserProfile = {
  name: "Kesavan",
  email: "kesavan@example.com"
};


Omit<T, K>

Omit is basically the opposite of Pick.

Suppose:

interface User {
  id: string;
  name: string;
  email: string;
  password: string;
}

We want a user object without the password.

type PublicUser = Omit<User, "password">;

Conceptually:

type PublicUser = {
  id: string;
  name: string;
  email: string;
};

Now:

const user: PublicUser = {
  id: "u101",
  name: "Kesavan",
  email: "kesavan@example.com"
};


Readonly<T>

We previously saw:

interface Product {
  readonly id: string;
  name: string;
}

You can make the entire object readonly:

type ReadonlyProduct = Readonly<Product>;

Now all properties become readonly.

const product: ReadonlyProduct = {
  id: "p1",
  name: "Laptop"
};

product.id = "p2";   // ❌
product.name = "PC"; // ❌
